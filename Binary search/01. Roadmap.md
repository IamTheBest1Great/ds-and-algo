## Pattern 1 — Classic Binary Search (Exact Target)

### 📖 Notes & Theory

**What it is**: The textbook binary search. The array is **sorted** and you need to find whether a target exists (or its index). Each step eliminates half the search space by comparing `mid` with the target.

**How to identify**:
- Array is explicitly sorted
- "Find index of X", "does X exist", "search in sorted array"
- Keywords: "sorted", "find", "search", "exists"

**Algorithm skeleton**:
```cpp
int binarySearch(vector<int>& nums, int target) {
    int lo = 0, hi = nums.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2; // avoid overflow — never use (lo+hi)/2
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1; // not found
}
```

**Three invariants to memorize**:
1. `lo <= hi` — loop continues while search space is non-empty
2. `mid = lo + (hi - lo) / 2` — always rounds DOWN (safe for all cases)
3. When `nums[mid] != target`: move `lo` to `mid+1` or `hi` to `mid-1` — NEVER stay at `mid`

**STL shortcuts (C++)**:
```cpp
// lower_bound: first position where value >= target
auto it = lower_bound(nums.begin(), nums.end(), target);

// upper_bound: first position where value > target
auto it = upper_bound(nums.begin(), nums.end(), target);

// Check existence:
bool found = binary_search(nums.begin(), nums.end(), target);
```

**Key insight**: The termination condition `lo <= hi` means the loop exits when `lo > hi`, i.e., the search space is empty. At that point, `lo` points to where the target WOULD be inserted (same as `lower_bound`).

## Pattern 2 — Left / Right Boundary (First / Last Occurrence)

### 📖 Notes & Theory

**What it is**: Find the **first** (leftmost) or **last** (rightmost) position of a target in a sorted array with duplicates. Unlike Pattern 1, hitting `nums[mid] == target` does NOT stop the search — you record the position and keep narrowing.

**How to identify**:
- "First occurrence", "last occurrence", "count of target", "starting and ending position"
- Sorted array with possible duplicates
- Keywords: "leftmost", "rightmost", "first position", "last position", "range"

**Left boundary (first occurrence)**:
```cpp
int leftBound(vector<int>& nums, int target) {
    int lo = 0, hi = nums.size() - 1, result = -1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) {
            result = mid;   // record candidate
            hi = mid - 1;  // keep searching LEFT
        } else if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return result;
}
```

**Right boundary (last occurrence)**:
```cpp
int rightBound(vector<int>& nums, int target) {
    int lo = 0, hi = nums.size() - 1, result = -1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) {
            result = mid;   // record candidate
            lo = mid + 1;  // keep searching RIGHT
        } else if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return result;
}
```

**Count of target**: `rightBound(target) - leftBound(target) + 1`

**Using STL**:
```cpp
int lo = lower_bound(nums.begin(), nums.end(), target) - nums.begin();
int hi = upper_bound(nums.begin(), nums.end(), target) - nums.begin() - 1;
// lo = first index of target (or insertion point if missing)
// hi = last index of target
// count = hi - lo + 1 (if lo <= hi, else 0)
```

**Key insight**: The only difference between left and right boundary search is which direction you continue searching when `nums[mid] == target`. Left boundary → shrink `hi`. Right boundary → advance `lo`.

## Pattern 3 — Binary Search on Answer (Minimize / Maximize)

### 📖 Notes & Theory

**What it is**: The search space is NOT an array — it's a **range of possible answers**. You binary search over this range and for each candidate answer `mid`, you check whether it is **feasible** using a helper function. The feasibility check is monotone: if `mid` is feasible, all values ≥ `mid` (for minimization) are also feasible.

**How to identify**:
- "Minimize the maximum", "maximize the minimum"
- "What is the smallest X such that condition holds?"
- The answer is a NUMBER and you can write a function `canDo(x)` that returns true/false
- Keywords: "at least", "at most", "minimum possible", "maximum possible", "threshold"

**Minimization template** (find smallest feasible value):
```cpp
int lo = minPossibleAnswer, hi = maxPossibleAnswer;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (feasible(mid)) hi = mid;     // mid works → try smaller
    else lo = mid + 1;               // mid too small → go larger
}
return lo; // smallest feasible value
```

**Maximization template** (find largest feasible value):
```cpp
int lo = minPossibleAnswer, hi = maxPossibleAnswer;
while (lo < hi) {
    int mid = lo + (hi - lo + 1) / 2; // round UP to avoid infinite loop
    if (feasible(mid)) lo = mid;       // mid works → try larger
    else hi = mid - 1;                 // mid too large → go smaller
}
return lo; // largest feasible value
```

**Why round up for maximization?** When `lo + 1 == hi`, `mid = lo + (hi-lo)/2 = lo`, making `lo = mid = lo` an infinite loop. Rounding up gives `mid = hi`, breaking out.

**Example — Koko Eating Bananas (875)**:
```cpp
bool canEat(vector<int>& piles, int speed, int h) {
    long long hours = 0;
    for (int p : piles) hours += (p + speed - 1) / speed; // ceil division
    return hours <= h;
}
// lo = 1, hi = max(piles)
// find smallest speed where canEat returns true
```

**Example — Split Array Largest Sum (410)**:
```cpp
bool canSplit(vector<int>& nums, int m, int maxSum) {
    int parts = 1, curr = 0;
    for (int x : nums) {
        if (curr + x > maxSum) { parts++; curr = 0; }
        curr += x;
    }
    return parts <= m;
}
// lo = max(nums), hi = sum(nums)
// find smallest maxSum where canSplit returns true
```

**Key insight**: The hard part is NOT the binary search — it's writing the `feasible()` function. Once you have `feasible()`, the binary search template is mechanical. Ask yourself: "If I fix the answer to X, can I verify in O(n) or O(n log n)?"

## Pattern 4 — Rotated / Shifted Sorted Array

### 📖 Notes & Theory

**What it is**: A sorted array that has been **rotated** at some pivot. It has two sorted halves. Binary search still works, but you must determine which half is sorted at each step before deciding which way to move.

**How to identify**:
- "Array was sorted then rotated"
- "Find minimum in rotated array", "search in rotated array"
- Keywords: "rotated", "shifted", "pivot", "circular sorted"

**Search in Rotated Array (33)**:
```cpp
int search(vector<int>& nums, int target) {
    int lo = 0, hi = nums.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) return mid;

        // Determine which half is sorted
        if (nums[lo] <= nums[mid]) {        // LEFT half is sorted
            if (nums[lo] <= target && target < nums[mid])
                hi = mid - 1;              // target in left half
            else
                lo = mid + 1;              // target in right half
        } else {                           // RIGHT half is sorted
            if (nums[mid] < target && target <= nums[hi])
                lo = mid + 1;              // target in right half
            else
                hi = mid - 1;             // target in left half
        }
    }
    return -1;
}
```

**Find Minimum in Rotated Array (153)**:
```cpp
int findMin(vector<int>& nums) {
    int lo = 0, hi = nums.size() - 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] > nums[hi]) lo = mid + 1; // min is in right half
        else hi = mid;                           // min is at mid or left
    }
    return nums[lo];
}
```

**With duplicates (81 / 154)** — when `nums[lo] == nums[mid] == nums[hi]`, you can't tell which half is sorted:
```cpp
// Shrink both ends by 1 when equal:
if (nums[lo] == nums[mid] && nums[mid] == nums[hi]) { lo++; hi--; }
```

**Key insight**: Always identify the **sorted half** first by comparing `nums[lo]` with `nums[mid]`. The sorted half provides a reliable range to check if the target falls within. Only one half is guaranteed sorted at each step.

## Pattern 5 — Search in 2D Matrix

### 📖 Notes & Theory

**What it is**: Binary search extended to a 2D matrix. Two main variants:
1. **Fully sorted matrix** (each row sorted, last of row < first of next row) — treat as flattened 1D array
2. **Staircase-sorted matrix** (each row sorted, each column sorted) — use top-right or bottom-left corner walk

**How to identify**:
- "Search in a matrix", "find target in sorted grid"
- "Each row is sorted", "each column is sorted"
- Keywords: "sorted matrix", "2D search", "grid"

**Fully sorted matrix (74) — treat as 1D**:
```cpp
bool searchMatrix(vector<vector<int>>& matrix, int target) {
    int m = matrix.size(), n = matrix[0].size();
    int lo = 0, hi = m * n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        int val = matrix[mid / n][mid % n]; // convert 1D index to 2D
        if (val == target) return true;
        else if (val < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return false;
}
```

**Staircase-sorted matrix (240) — start at top-right corner**:
```cpp
bool searchMatrix(vector<vector<int>>& matrix, int target) {
    int row = 0, col = matrix[0].size() - 1; // top-right corner
    while (row < matrix.size() && col >= 0) {
        if (matrix[row][col] == target) return true;
        else if (matrix[row][col] > target) col--; // eliminate column
        else row++;                                 // eliminate row
    }
    return false;
}
```

**Row-wise binary search (general)**:
```cpp
// Binary search each row independently when only rows are sorted
for (auto& row : matrix) {
    if (binary_search(row.begin(), row.end(), target)) return true;
}
```

**Key insight**: For the staircase matrix, starting at top-right means: if current > target, move left (eliminate this column); if current < target, move down (eliminate this row). Each step eliminates a full row or column — O(m + n) total.

## Pattern 6 — Peak / Valley Finding

### 📖 Notes & Theory

**What it is**: Find a **local maximum or minimum** without the array being globally sorted. The key insight is that moving toward the larger neighbor always leads to a peak — this creates a monotone property that binary search can exploit.

**How to identify**:
- "Find a peak element", "local maximum", "mountain array"
- "Element greater than both neighbors"
- Keywords: "peak", "valley", "mountain", "local max/min"

**Find Peak Element (162)**:
```cpp
int findPeakElement(vector<int>& nums) {
    int lo = 0, hi = nums.size() - 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] > nums[mid + 1]) hi = mid;     // peak is at mid or left
        else lo = mid + 1;                            // peak is to the right
    }
    return lo; // lo == hi = peak index
}
```

**Why this works**: If `nums[mid] < nums[mid+1]`, there must be a peak to the right (the sequence is rising — it must eventually fall). If `nums[mid] > nums[mid+1]`, there must be a peak at `mid` or to the left.

**Mountain Array — find peak then binary search each side (1095)**:
```cpp

// Phase 2: binary search ascending side [0, peak] for target
// Phase 3: binary search descending side [peak, n-1] for target
//          (reversed comparisons: move right when too large)
```

**Check if array is sorted ascending then descending (valid mountain)**:
```cpp
// Find peak, check both sides are strictly monotone
```

**Key insight**: You don't need the array to be sorted. You only need the **slope direction** at `mid`. Comparing `nums[mid]` and `nums[mid+1]` tells you which side a peak lies on.

## Pattern 7 — Binary Search on Floating Point / Precision

### 📖 Notes & Theory

**What it is**: Binary search over a **continuous real-valued range**. Instead of a termination condition based on `lo <= hi` (integers), you run for a fixed number of iterations or until `hi - lo < epsilon`.

**How to identify**:
- "Find the square root to N decimal places"
- "Find the nth root of a number"
- "Smallest real number satisfying condition"
- Keywords: "precision", "decimal", "real-valued", "square root", "nth root"

**Algorithm skeleton**:
```cpp
double binarySearchFloat(double target, int precision = 100) {
    double lo = 0, hi = target; // or hi = 1.0 if answer ≤ 1
    for (int i = 0; i < precision; i++) { // 100 iterations ≈ 10^-30 precision
        double mid = (lo + hi) / 2.0;
        if (f(mid) < target) lo = mid;
        else hi = mid;
    }
    return (lo + hi) / 2.0;
}
```

**Square root (69 — integer)**:
```cpp
int mySqrt(int x) {
    if (x < 2) return x;
    long lo = 1, hi = x / 2;
    while (lo <= hi) {
        long mid = lo + (hi - lo) / 2;
        if (mid * mid == x) return mid;
        else if (mid * mid < x) lo = mid + 1;
        else hi = mid - 1;
    }
    return hi; // floor of sqrt
}
```

**Nth root (real-valued)**:
```cpp
double nthRoot(double x, int n) {
    double lo = 0, hi = max(1.0, x);
    for (int i = 0; i < 200; i++) {
        double mid = (lo + hi) / 2.0;
        if (pow(mid, n) < x) lo = mid;
        else hi = mid;
    }
    return (lo + hi) / 2.0;
}
```

**Key insight**: For floating point BS, use iteration count (100–200) rather than `lo < hi - eps`. Each iteration halves the search space, so 100 iterations gives precision of `(hi-lo) / 2^100` which is essentially zero for any reasonable range.

**Edge case**: When the answer could be between 0 and 1, set `hi = 1.0`. When it could be > input, set `hi = input`. When unsure, set `hi = 1e9`.

## Pattern 8 — K-th Element (Median / Order Statistics)

### 📖 Notes & Theory

**What it is**: Find the K-th smallest (or largest) element across a complex structure — two sorted arrays, a sorted matrix, or all possible pairs. Direct sorting would be too slow. Binary search on the **value** of the answer is combined with a counting function.

**How to identify**:
- "Median of two sorted arrays", "Kth smallest in matrix", "Kth smallest pair"
- "Find Kth smallest element across multiple sorted structures"
- Keywords: "Kth smallest", "median", "order statistic"

**Median of Two Sorted Arrays (4) — binary search on partition**:
```cpp
double findMedianSortedArrays(vector<int>& A, vector<int>& B) {
    if (A.size() > B.size()) swap(A, B); // ensure A is smaller
    int m = A.size(), n = B.size();
    int lo = 0, hi = m;

    while (lo <= hi) {
        int partA = lo + (hi - lo) / 2;
        int partB = (m + n + 1) / 2 - partA;

        int maxLeftA  = (partA == 0) ? INT_MIN : A[partA - 1];
        int minRightA = (partA == m) ? INT_MAX : A[partA];
        int maxLeftB  = (partB == 0) ? INT_MIN : B[partB - 1];
        int minRightB = (partB == n) ? INT_MAX : B[partB];

        if (maxLeftA <= minRightB && maxLeftB <= minRightA) {
            // Correct partition found
            if ((m + n) % 2 == 1) return max(maxLeftA, maxLeftB);
            return (max(maxLeftA, maxLeftB) + min(minRightA, minRightB)) / 2.0;
        } else if (maxLeftA > minRightB) hi = partA - 1;
        else lo = partA + 1;
    }
    return 0.0;
}
```

**Kth Smallest in Sorted Matrix (378) — BS on value**:
```cpp
int kthSmallest(vector<vector<int>>& matrix, int k) {
    int n = matrix.size();
    int lo = matrix[0][0], hi = matrix[n-1][n-1];

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        // Count elements <= mid using staircase walk
        int count = 0, col = n - 1;
        for (int row = 0; row < n; row++) {
            while (col >= 0 && matrix[row][col] > mid) col--;
            count += col + 1;
        }
        if (count < k) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
```

**Key insight for Median of Two Arrays**: Instead of searching for a value, search for the correct **partition point** in the smaller array. The correct partition is when `maxLeft ≤ minRight` on both sides.

## Pattern 9 — Binary Search + Greedy / Feasibility Check

### 📖 Notes & Theory

**What it is**: The binary search narrows down the answer, but the feasibility check at each `mid` requires a **non-trivial algorithm** — typically a greedy pass, simulation, or counting that runs in O(n) or O(n log n). This pattern appears in optimization problems where "can we achieve X?" is easier to answer than "what is the best X?"

**How to identify**:
- "Can we do this task in X days/time/cost?"
- "Is it possible to achieve X with these constraints?"
- The feasibility check requires more than O(1) — it needs its own algorithm
- Keywords: "minimum days", "can we", "feasible", "possible", "allocate"

**General structure**:

**Minimum Number of Days to Make Bouquets (1482)**:
```cpp
bool feasible(vector<int>& bloomDay, int m, int k, int day) {
    int bouquets = 0, consecutive = 0;
    for (int d : bloomDay) {
        if (d <= day) { consecutive++; if (consecutive == k) { bouquets++; consecutive = 0; } }
        else consecutive = 0;
    }
    return bouquets >= m;
```

**Magnetic Force Between Balls (1552)** — maximize minimum distance:
```cpp
bool feasible(vector<int>& pos, int m, int minDist) {
    int placed = 1, last = pos[0];
    for (int i = 1; i < pos.size(); i++) {
        if (pos[i] - last >= minDist) { placed++; last = pos[i]; }
    }
    return placed >= m;
}
// Maximize: use round-up mid template
```

**Key insight**: The monotone property must hold for `feasible()`. For minimization: if `feasible(x)` is true, then `feasible(x+1)` is also true. For maximization: if `feasible(x)` is true, then `feasible(x-1)` is also true.

## Pattern 10 — Advanced: Binary Search on Segment / Monotone Function

### 📖 Notes & Theory

**What it is**: The most general form of binary search. You binary search over a domain where some function `f(x)` is **monotone** (always increasing or always decreasing), but the domain is not a simple sorted array. Includes prefix-sum applications, range queries, and abstract monotone functions.

**How to identify**:
- The problem can be modeled as: "find the smallest x such that f(x) ≥ target" where f is non-decreasing
- "How many elements ≤ x?" as a monotone function
- Segment trees, Fenwick trees, or prefix sums as the counting oracle
- Keywords: "count elements ≤ x", "cumulative", "number of elements in range"

**Kth Missing Positive (1539)** — monotone count function:
```cpp
// f(x) = how many positive integers ≤ x are missing = x - count(elements ≤ x)
// find smallest x where f(x) >= k
int findKthPositive(vector<int>& arr, int k) {
    int lo = 1, hi = arr.back() + k;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        // missing count up to mid = mid - (# arr elements <= mid)
        int missing = mid - (int)(upper_bound(arr.begin(), arr.end(), mid) - arr.begin());
        if (missing < k) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
```

## Quick Reference — Common Mistakes

| Mistake | Correct Approach |
|---|---|
| Using `(lo + hi) / 2` for mid | Always use `lo + (hi - lo) / 2` to prevent integer overflow |
| Infinite loop in maximization template | Round mid UP: `lo + (hi - lo + 1) / 2` when doing `lo = mid` |
| Wrong loop condition (`lo < hi` vs `lo <= hi`) | `lo <= hi` for exact search (P1); `lo < hi` for boundary/answer search (P2–P10) |
| Shrinking wrong side when target not found | In P1: `lo = mid+1` or `hi = mid-1` — NEVER stay at mid |
| Not defining search space bounds correctly | lo = smallest possible answer, hi = largest possible answer — think carefully |
| Forgetting that `lo` after loop = insert position | After P1 loop exits with -1, `lo` = position where target would be inserted |
| Pattern 4: not handling duplicates | When `nums[lo] == nums[mid] == nums[hi]`, shrink both ends: `lo++; hi--` |
| Pattern 6: comparing `mid` with `mid-1` instead of `mid+1` | Compare `nums[mid]` vs `nums[mid+1]` — avoids out-of-bounds and is cleaner |
| Pattern 3: feasibility function not monotone | Double-check: if feasible(x) is true, is feasible(x+1) also true? Must be yes |
| Pattern 8: Median — not ensuring A is the smaller array | `if (A.size() > B.size()) swap(A, B)` — binary search on smaller array only |
| Off-by-one in ceil division | `ceil(a/b)` in integers = `(a + b - 1) / b` — use this in feasibility functions |
| Pattern 2: stopping when `nums[mid] == target` | In boundary search, RECORD and keep going (shrink hi for left, advance lo for right) |
