## Pattern 1 — Fixed Window (Sum / Average)

### 📖 Notes & Theory

**What it is**: The simplest sliding window. The window size is **exactly K** and never changes. You add the incoming right element and subtract the outgoing left element as the window slides — each step is O(1).

**How to identify**:
- Problem explicitly states "subarray of size K" or "exactly K consecutive"
- Asks for maximum, minimum, average, or count over fixed-length subarrays
- Keywords: "K consecutive", "size K", "fixed length", "window of size K"

**Algorithm skeleton**:
```cpp
int maxSumFixedWindow(vector<int>& nums, int k) {
    int n = nums.size();
    int windowSum = 0;

    // Build first window
    for (int i = 0; i < k; i++) windowSum += nums[i];

    int maxSum = windowSum;

    // Slide the window
    for (int i = k; i < n; i++) {
        windowSum += nums[i];       // add incoming (right)
        windowSum -= nums[i - k];   // remove outgoing (left)
        maxSum = max(maxSum, windowSum);
    }
    return maxSum;
}
```

**Average variant (643)**:
```cpp
// Same logic — divide windowSum by k at each step
double maxAvg = (double)windowSum / k;
for (int i = k; i < n; i++) {
    windowSum += nums[i] - nums[i - k];
    maxAvg = max(maxAvg, (double)windowSum / k);
}
```

**Count subarrays ≥ threshold (1343)**:
```cpp
// Count windows where windowSum / k >= threshold
// i.e., windowSum >= threshold * k
int count = 0;
if (windowSum >= (long long)threshold * k) count++;
for (int i = k; i < n; i++) {
    windowSum += nums[i] - nums[i - k];
    if (windowSum >= (long long)threshold * k) count++;
}
```

**Key insight**: The "add right, subtract left" pattern runs the entire array in O(n) with O(1) extra space. Always build the first window separately, then slide.

## Pattern 2 — Fixed Window (Frequency / Anagram)

### 📖 Notes & Theory

**What it is**: A fixed-size window where you track **character or element frequencies** rather than a numeric sum. Sliding the window means updating the frequency map: increment for the new right element, decrement for the outgoing left element.

**How to identify**:
- "Find all anagrams", "permutation exists in string", "check window is rearrangement of pattern"
- Window size = length of pattern string
- Keywords: "anagram", "permutation", "rearrangement", "character frequency"

**Algorithm skeleton (Find All Anagrams — 438)**:
```cpp
vector<int> findAnagrams(string s, string p) {
    if (s.size() < p.size()) return {};
    vector<int> pFreq(26, 0), wFreq(26, 0);
    for (char c : p) pFreq[c - 'a']++;

    int k = p.size();
    vector<int> result;

    // Build first window
    for (int i = 0; i < k; i++) wFreq[s[i] - 'a']++;

    if (wFreq == pFreq) result.push_back(0);

    // Slide
    for (int i = k; i < s.size(); i++) {
        wFreq[s[i] - 'a']++;           // add right
        wFreq[s[i - k] - 'a']--;       // remove left
        if (wFreq == pFreq) result.push_back(i - k + 1);
    }
    return result;
}
```

**Optimized: track `diff` count instead of comparing arrays**:
```cpp
// diff = number of characters where wFreq[c] != pFreq[c]
// Window is valid when diff == 0
// On adding s[i]:
//   if wFreq[c] == pFreq[c] before increment → diff++
//   if wFreq[c] == pFreq[c] after increment  → diff--
// Same logic for removal
```

**Key insight**: Comparing two 26-element arrays is O(26) = O(1) for fixed alphabet. The `diff` optimization avoids even this constant cost. Use `diff` when the alphabet is large or the comparison is expensive.

## Pattern 3 — Variable Window (Longest, At Most K)

### 📖 Notes & Theory

**What it is**: The window **grows** by moving `right` and **shrinks** by moving `left` whenever a constraint is violated. The goal is to find the **longest** valid window. This is the most commonly asked sliding window pattern.

**How to identify**:
- "Longest substring/subarray satisfying X"
- "At most K distinct characters/zeros/flips"
- "No repeating characters"
- Keywords: "longest", "maximum length", "at most K"

**Algorithm skeleton**:
```cpp
int left = 0, maxLen = 0;
unordered_map<char, int> freq; // or array[26], or int count

for (int right = 0; right < n; right++) {
    // 1. Expand: add s[right] to window state
    freq[s[right]]++;

    // 2. Shrink: while constraint violated, move left
    while (freq.size() > k) {           // example: at most k distinct
        freq[s[left]]--;
        if (freq[s[left]] == 0) freq.erase(s[left]);
        left++;
    }

    // 3. Update answer: window [left, right] is valid
    maxLen = max(maxLen, right - left + 1);
}
return maxLen;
```

**Longest Substring Without Repeating (3)**:
```cpp
unordered_map<char, int> lastSeen;
int left = 0, maxLen = 0;
for (int right = 0; right < n; right++) {
    if (lastSeen.count(s[right]) && lastSeen[s[right]] >= left) {
        left = lastSeen[s[right]] + 1; // jump left past duplicate
    }
    lastSeen[s[right]] = right;
    maxLen = max(maxLen, right - left + 1);
}
```

**At most K zeros (Max Consecutive Ones III — 1004)**:
```cpp
int left = 0, zeros = 0, maxLen = 0;
for (int right = 0; right < n; right++) {
    if (nums[right] == 0) zeros++;
    while (zeros > k) {
        if (nums[left++] == 0) zeros--;
    }
    maxLen = max(maxLen, right - left + 1);
}
```

**Key insight**: The window is always valid after the `while` loop. The answer is recorded at every step after shrinking — meaning you always process a valid window before moving on.

**When to use `if` vs `while` for shrinking**:
- Use `while` (standard) — shrinks until valid, works always
- Use `if` (optimization for "longest") — since we only care about growing, one shrink step suffices; window never needs to shrink more than 1 at a time when tracking max length

## Pattern 4 — Variable Window (Shortest, At Least Target)

### 📖 Notes & Theory

**What it is**: The window shrinks **as aggressively as possible** once a condition is met. The goal is to find the **shortest** valid window. The shrink happens inside a `while` loop that runs as long as the window remains valid — the opposite of Pattern 3.

**How to identify**:
- "Minimum length subarray with sum ≥ target"
- "Shortest subarray satisfying condition"
- Keywords: "minimum length", "shortest", "smallest subarray", "at least"

**Algorithm skeleton**:
```cpp
int left = 0, minLen = INT_MAX;
int windowSum = 0;

for (int right = 0; right < n; right++) {
    windowSum += nums[right]; // expand

    // Shrink as long as window is valid
    while (windowSum >= target) {
        minLen = min(minLen, right - left + 1); // record BEFORE shrinking
        windowSum -= nums[left++];              // shrink
    }
}
return minLen == INT_MAX ? 0 : minLen;
```

**Minimum Window Substring (76)** — track how many required chars are "satisfied":
```cpp
unordered_map<char,int> need, have;
for (char c : t) need[c]++;
int formed = 0, required = need.size();
int left = 0, minLen = INT_MAX, start = 0;

for (int right = 0; right < s.size(); right++) {
    char c = s[right];
    have[c]++;
    if (need.count(c) && have[c] == need[c]) formed++;

    while (formed == required) {        // window is valid → shrink
        if (right - left + 1 < minLen) { minLen = right - left + 1; start = left; }
        char l = s[left++];
        have[l]--;
        if (need.count(l) && have[l] < need[l]) formed--;
    }
}
return minLen == INT_MAX ? "" : s.substr(start, minLen);
```

**Key insight**: The critical difference from Pattern 3 — in Pattern 3 you record the answer AFTER shrinking (window is valid). In Pattern 4 you record the answer WHILE the window is still valid (BEFORE the shrink removes validity).

**Negative numbers edge case**: When the array has negative numbers, use a deque-based approach (Pattern 6) rather than this template, since shrinking is no longer monotone.

## Pattern 5 — Exactly K (atMost Trick)

### 📖 Notes & Theory

**What it is**: Count subarrays with **exactly K** of something. Direct sliding window won't work because "exactly K" windows can't shrink cleanly. The trick: decompose into two "at most" problems.

**The formula**:
```
count(exactly K) = count(at most K) − count(at most K−1)
```

**How to identify**:
- "Count subarrays with exactly K distinct elements"
- "Count subarrays with exactly K odd numbers"
- "Number of subarrays where [some count] = K"
- Keywords: "exactly K", "count subarrays", "number of subarrays"

**atMost(K) helper**:
```cpp
int atMost(vector<int>& nums, int k) {
    unordered_map<int, int> freq;
    int left = 0, count = 0;

    for (int right = 0; right < nums.size(); right++) {
        freq[nums[right]]++;

        while (freq.size() > k) {           // violated: too many distinct
            freq[nums[left]]--;
            if (freq[nums[left]] == 0) freq.erase(nums[left]);
            left++;
        }

        count += right - left + 1;          // all subarrays ending at right
    }
    return count;
}

// Main:
int subarraysWithKDistinct(vector<int>& nums, int k) {
    return atMost(nums, k) - atMost(nums, k - 1);
}
```

**Why `right - left + 1`?** Every time the window `[left, right]` is valid, all subarrays `[left, right], [left+1, right], ..., [right, right]` are also valid. Their count is `right - left + 1`.

**Subarrays with K Odd Numbers (1248)**:
```cpp
// atMost(k) = count subarrays with AT MOST k odd numbers
int atMostOdd(vector<int>& nums, int k) {
    int left = 0, odds = 0, count = 0;
    for (int right = 0; right < nums.size(); right++) {
        if (nums[right] % 2 == 1) odds++;
        while (odds > k) {
            if (nums[left++] % 2 == 1) odds--;
        }
        count += right - left + 1;
    }
    return count;
}
int numberOfSubarrays(vector<int>& nums, int k) {
    return atMostOdd(nums, k) - atMostOdd(nums, k - 1);
}
```

**Key insight**: The "atMost" function is just Pattern 3 (variable longest) but counting subarrays instead of tracking max length. The subtraction cancels out the extras, leaving exactly-K windows.

## Pattern 6 — Window with Monotonic Deque

### 📖 Notes & Theory

**What it is**: A sliding window where you need the **maximum or minimum** of the current window in O(1). A regular array can't do this efficiently — you'd need O(k) per step. A **monotonic deque** (double-ended queue) maintains elements in sorted order, giving O(1) access to the window's extremum.

**How to identify**:
- "Maximum of every window of size K"
- "Sliding window where constraint involves the max or min of the window"
- Keywords: "maximum in window", "minimum in window", "constrained by range"

**Algorithm skeleton (Sliding Window Maximum — 239)**:
```cpp
vector<int> maxSlidingWindow(vector<int>& nums, int k) {
    deque<int> dq; // stores INDICES, front = index of current max
    vector<int> result;

    for (int i = 0; i < nums.size(); i++) {
        // Remove elements outside window
        while (!dq.empty() && dq.front() <= i - k) dq.pop_front();

        // Maintain decreasing order: remove smaller elements from back
        while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();

        dq.push_back(i);

        // Window fully formed
        if (i >= k - 1) result.push_back(nums[dq.front()]);
    }
    return result;
}
```

**Variable window with max-min constraint (1438)**:
```cpp
// Longest subarray where max - min <= limit
deque<int> maxDq, minDq; // decreasing and increasing
int left = 0, maxLen = 0;

for (int right = 0; right < n; right++) {
    while (!maxDq.empty() && nums[maxDq.back()] <= nums[right]) maxDq.pop_back();
    while (!minDq.empty() && nums[minDq.back()] >= nums[right]) minDq.pop_back();
    maxDq.push_back(right);
    minDq.push_back(right);

    while (nums[maxDq.front()] - nums[minDq.front()] > limit) {
        left++;
        if (maxDq.front() < left) maxDq.pop_front();
        if (minDq.front() < left) minDq.pop_front();
    }
    maxLen = max(maxLen, right - left + 1);
}
```

**Key insight**: The deque always stores indices in order. The front is always the max (or min) of the current window. Elements are popped from the back if they're dominated by the new element, and from the front if they slide out of the window.

## Pattern 7 — String Replacement / Character Budget

### 📖 Notes & Theory

**What it is**: You have a **budget** of K replacements/flips. You want the longest window where all elements can be made equal (or satisfy some condition) using at most K changes. The key trick: the number of replacements needed = window size − count of the most frequent element.

**How to identify**:
- "Longest substring after replacing at most K characters"
- "Max consecutive ones after flipping K zeros"
- "Longest subarray after changing at most K elements"
- Keywords: "replace", "flip", "change", "at most K operations", "budget"

**Algorithm skeleton (Longest Repeating Character Replacement — 424)**:
```cpp
int characterReplacement(string s, int k) {
    vector<int> freq(26, 0);
    int left = 0, maxFreq = 0, maxLen = 0;

    for (int right = 0; right < s.size(); right++) {
        freq[s[right] - 'A']++;
        maxFreq = max(maxFreq, freq[s[right] - 'A']);

        // replacements needed = windowSize - maxFreq
        // If > k, shrink
        if ((right - left + 1) - maxFreq > k) {
            freq[s[left] - 'A']--;
            left++;
            // Note: maxFreq is NOT decremented — it's a running max
            // This is intentional: we only care if we can do BETTER
        }

        maxLen = max(maxLen, right - left + 1);
    }
    return maxLen;
}
```

**Why NOT decrement `maxFreq`?** We only want to grow the answer. If the window shrinks, it shrinks by exactly 1 (no benefit to shrink more). `maxFreq` only ever needs to increase to improve our answer.

```cpp
// replacements needed = windowSize - count_of_ones = count_of_zeros
// condition: zeros <= k
```

**Maximize the Confusion (2024)** — apply the template twice (once for 'T', once for 'F'):
```cpp
// Run characterReplacement logic treating 'T' as dominant, then 'F'
// Answer = max of both runs
```

**Key insight**: The window only needs to shrink by 1 step when the budget is exceeded. We never need to "re-shrink" multiple times in this pattern — the window monotonically grows or stays the same size, which is why this gives O(n).

## Pattern 8 — Subarray Count (Contribution / Prefix Sum)

### 📖 Notes & Theory

**What it is**: Count the **number** of valid subarrays rather than finding the longest/shortest one. When the window is valid, every subarray ending at `right` and starting anywhere from `left` to `right` is counted. This gives `right - left + 1` valid subarrays at each step.

**How to identify**:
- "Count the number of subarrays where product < K"
- "How many subarrays satisfy condition X"
- Output is a COUNT, not a length
- Keywords: "count subarrays", "number of subarrays", "how many"

**Algorithm skeleton (Product Less Than K — 713)**:
```cpp
int numSubarrayProductLessThanK(vector<int>& nums, int k) {
    if (k <= 1) return 0;
    int left = 0, product = 1, count = 0;

    for (int right = 0; right < nums.size(); right++) {
        product *= nums[right];

        while (product >= k) product /= nums[left++];

        // All subarrays [left..right], [left+1..right], ..., [right..right]
        count += right - left + 1;
    }
    return count;
}
```

**Count Good Subarrays (2537)** — count subarrays with exactly K equal pairs:
```cpp
// Use atMost trick from Pattern 5
// count(exactly K pairs) = atMost(K) - atMost(K-1)
// In atMost: count += right - left + 1 per step
```

**Score < K (2261)** — score = sum × length:
```cpp
// When score >= k, shrink left
// Each valid window contributes right - left + 1 subarrays
```

**Key insight**: The `right - left + 1` contribution formula works because the window defines the LONGEST valid subarray ending at `right`. All shorter subarrays ending at `right` are also valid (monotone property). This only holds when shrinking the window preserves validity.

## Pattern 9 — Multi-Source / Circular Window

### 📖 Notes & Theory

**What it is**: The window wraps around the array (circular), or you must pick elements from **both ends** of an array. These problems reduce to a sliding window on a transformed or doubled array.

**How to identify**:
- "Pick K cards from either end", "circular subarray", "max sum wrapping around"
- "Choose from left OR right"
- Keywords: "from either end", "circular", "wrap around", "both ends"

**Cards from Both Ends (1423)** — inversion trick:
```cpp
// Total - min(middle subarray of size n-k)
// Picking k from ends = removing a contiguous block of n-k from the middle
int maxScore(vector<int>& cards, int k) {
    int n = cards.size(), total = 0;
    for (int x : cards) total += x;

    int windowSize = n - k;
    if (windowSize == 0) return total;

    // Find minimum sum window of size (n-k)
    int windowSum = 0;
    for (int i = 0; i < windowSize; i++) windowSum += cards[i];
    int minWindow = windowSum;

    for (int i = windowSize; i < n; i++) {
        windowSum += cards[i] - cards[i - windowSize];
        minWindow = min(minWindow, windowSum);
    }
    return total - minWindow;
}
```

**Circular fixed window (1652 — Defuse the Bomb)**:
```cpp
// Extend array: simulate by using modular index i % n
for (int i = 0; i < n; i++) {
    // window from i+1 to i+k (wrapping)
    result[i] = sum of nums[(i+1)%n] ... nums[(i+k)%n]
}
// Build with prefix sum on doubled array or use modular sliding window
```

**Maximum Sum Circular Subarray (918)**:
```cpp
// Case 1: max subarray is non-circular → Kadane's algorithm
// Case 2: max subarray wraps → total - min subarray (also Kadane's)
// Answer = max(case1, total - minSubarray)
// Edge case: if all elements negative → return case1 (can't take empty)
```

**Key insight**: Circular = doubled array. For "pick from both ends", invert the problem to "which middle subarray NOT to pick."

## Pattern 10 — 2D Sliding Window

### 📖 Notes & Theory

**What it is**: Extend the 1D sliding window to a **2D matrix**. The approach: apply 1D sliding window logic **column by column** using **prefix column sums**, then slide a fixed-height band across rows.

**How to identify**:
- "Max sum submatrix of size K×K"
- "Count 1s in a subgrid", "submatrix with sum ≤ target"
- Keywords: "submatrix", "grid", "2D window", "K×K"

**Algorithm skeleton (Max Sum K×K Subgrid)**:
```cpp
int maxSumSubmatrix(vector<vector<int>>& matrix, int k) {
    int m = matrix.size(), n = matrix[0].size();
    int maxSum = INT_MIN;

    // Fix left and right column boundaries
    for (int left = 0; left < n; left++) {
        vector<int> colSum(m, 0);

        for (int right = left; right < n; right++) {
            // Accumulate column sums between left and right
            for (int row = 0; row < m; row++) colSum[row] += matrix[row][right];

            // Now find max subarray of size k in colSum (1D fixed window)
            int windowSum = 0;
            for (int i = 0; i < k; i++) windowSum += colSum[i];
            maxSum = max(maxSum, windowSum);
            for (int i = k; i < m; i++) {
                windowSum += colSum[i] - colSum[i - k];
                maxSum = max(maxSum, windowSum);
            }
        }
    }
    return maxSum;
}
```

**Count subarrays (1504)**:
```cpp
// For each row, compute height[] = number of consecutive 1s ending at this row per column
// Then for each row, use 1D sliding window on height[] to count valid windows
```

**Key insight**: 2D window = **fix two boundaries** (columns) + **run 1D window** on compressed column sums. This reduces O(m²n²) brute force to O(m²n) or O(mn²).

## Quick Reference — Common Mistakes

| Mistake | Correct Approach |
|---|---|
| Using `if` to shrink in Pattern 4 (shortest) | Use `while` — shrink as long as window is still valid to minimize length |
| Recording answer before shrinking in Pattern 3 | Record AFTER shrinking (window must be valid when you record) |
| Recording answer after shrinking in Pattern 4 | Record BEFORE shrinking (window is valid at start of `while`, not after) |
| Comparing full frequency arrays each step | Track a `diff` counter or `formed` count — update incrementally in O(1) |
| Forgetting that window length = `right - left + 1` | NOT `right - left` — both endpoints are inclusive |
| Decrementing `maxFreq` when shrinking in Pattern 7 | Don't decrement — `maxFreq` is a monotone running max; shrink by just 1 |
| Using `while` to shrink in Pattern 7 (budget window) | Use `if` — window only needs to shrink by 1 when budget exceeded |
| Not initializing `left = 0` before outer loop | Always reset `left` and window state before starting the for loop |
| Pattern 5: directly counting "exactly K" windows | Use `atMost(K) - atMost(K-1)` decomposition — direct counting breaks |
| Pattern 6: storing values instead of indices in deque | Store INDICES — you need them to check if front is outside the window |
| Pattern 9: forgetting the edge case when all elements negative in 918 | If `total - minSubarray == 0`, all elements are negative — return Kadane result |
| Pattern 1: integer overflow when multiplying threshold × k | Cast to `long long` before multiplication |
