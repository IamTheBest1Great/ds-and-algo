## Pattern 1 — Basic Stack Simulation

### 📖 Notes & Theory

**What it is**: The most fundamental use of a stack — LIFO order to simulate a process. You push items onto the stack and pop them when a condition is met. No special ordering required; just the "most recent item first" property.

**How to identify**:
- "Process elements in reverse order", "undo last action", "valid sequence of operations"
- Keywords: "push", "pop", "simulate", "last in first out"
- If the problem says "most recently seen X" → stack

**Algorithm skeleton**:
```cpp
stack<int> st;

for (int x : input) {
    if (shouldPop(x, st)) {
        st.pop();
    } else {
        st.push(x);
    }
}
// remaining elements in stack = answer
```

**Key insight**: The stack holds "unresolved" elements — things waiting for a match or condition. When the condition is met, you pop. At the end, the stack contains what was never resolved.

## Pattern 2 — Monotonic Stack (Next Greater / Smaller)

### 📖 Notes & Theory

**What it is**: A stack that is always maintained in **monotonically increasing or decreasing** order. When a new element breaks the monotonicity, you pop — and at the moment of popping, you've found the "next greater" or "next smaller" element for the popped item.

**How to identify**:
- "Next greater element", "next smaller element", "previous greater/smaller"
- "Daily temperatures", "number of visible people", "span of stock"
- Any problem where each element needs to find the nearest element satisfying a condition

**Two flavors**:
- **Monotonic Decreasing Stack** → finds **Next Greater Element** (pop when current > top)
- **Monotonic Increasing Stack** → finds **Next Smaller Element** (pop when current < top)

**Algorithm skeleton (Next Greater Element)**:
```cpp
vector<int> nextGreater(vector<int>& nums) {
    int n = nums.size();
    vector<int> res(n, -1);
    stack<int> st; // stores indices

    for (int i = 0; i < n; i++) {
        // Pop all elements smaller than current
        while (!st.empty() && nums[st.top()] < nums[i]) {
            res[st.top()] = nums[i]; // current is the NGE for st.top()
            st.pop();
        }
        st.push(i);
    }
    return res;
}
```

**Circular array trick (503)**: Loop twice (`i % n`) to simulate wrap-around.

**Key insight**: Store **indices** in the stack (not values) — you need to know WHERE to record the answer.

## Pattern 3 — Histogram / Largest Rectangle

### 📖 Notes & Theory

**What it is**: Use a monotonic stack to compute areas efficiently in histogram-type problems. The key operation: when a bar is shorter than the top of the stack, you can compute the area for the popped bar using the current index and the new stack top.

**How to identify**:
- "Largest rectangle in histogram", "trapping rain water", "sum of subarray minimums"
- Any problem with "area" and an array of heights/values
- Keywords: "histogram", "container", "trap", "rectangle"

**Algorithm skeleton (Largest Rectangle)**:
```cpp
int largestRectangle(vector<int>& heights) {
    stack<int> st;
    int maxArea = 0;
    heights.push_back(0); // sentinel to flush remaining stack

    for (int i = 0; i < heights.size(); i++) {
        while (!st.empty() && heights[st.top()] > heights[i]) {
            int h = heights[st.top()]; st.pop();
            int w = st.empty() ? i : i - st.top() - 1;
            maxArea = max(maxArea, h * w);
        }
        st.push(i);
    }
    return maxArea;
}
```

**Trapping Rain Water (42)**:
Two approaches:
1. **Two pointers** (O(1) space) — left/right walls converging
2. **Monotonic stack** — pop when taller bar found, compute trapped water

**Key insight**: When you pop from the stack, the width of the rectangle extends from the new stack top to the current index. The sentinel `0` at the end forces all remaining elements to be processed.

## Pattern 4 — Parentheses / Bracket Matching

### 📖 Notes & Theory

**What it is**: Use a stack to match opening brackets with closing ones. When you see a closing bracket, check if the top of the stack is its matching opener. Any mismatch or leftover = invalid.

**How to identify**:
- "Valid parentheses", "minimum removals to make valid", "score of parentheses"
- "Longest valid parentheses substring"
- Keywords: "brackets", "balance", "matching", "nesting"

**Algorithm skeleton (Validate)**:
```cpp
bool isValid(string s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push(c);
        } else {
            if (st.empty()) return false;
            if (c == ')' && st.top() != '(') return false;
            if (c == ']' && st.top() != '[') return false;
            if (c == '}' && st.top() != '{') return false;
            st.pop();
        }
    }
    return st.empty();
}
```

**Longest Valid Parentheses (32)** — store **indices** in the stack:
```cpp
stack<int> st;
st.push(-1); // base index
for (int i = 0; i < s.size(); i++) {
    if (s[i] == '(') st.push(i);
    else {
        st.pop();
        if (st.empty()) st.push(i); // new base
        else maxLen = max(maxLen, i - st.top());
    }
}
```

**Minimum Removals**: Count unmatched opens (left over in stack) + unmatched closes (popped to empty stack).

## Pattern 5 — Expression Evaluation / Calculator

### 📖 Notes & Theory

**What it is**: Use a stack to handle operator precedence and evaluate arithmetic or boolean expressions. The stack stores intermediate operands and signs. Parentheses trigger recursive processing or stack-state saving.

**How to identify**:
- "Implement a calculator", "evaluate reverse polish notation", "basic calculator"
- "Infix to postfix", "evaluate expression with +, -, *, /"
- Keywords: "evaluate", "calculate", "expression", "operator", "precedence"

**Reverse Polish Notation (150)** — simplest form:
```cpp
int evalRPN(vector<string>& tokens) {
    stack<long long> st;
    for (auto& t : tokens) {
        if (t == "+" || t == "-" || t == "*" || t == "/") {
            long long b = st.top(); st.pop();
            long long a = st.top(); st.pop();
            if (t == "+") st.push(a + b);
            else if (t == "-") st.push(a - b);
            else if (t == "*") st.push(a * b);
            else st.push(a / b);
        } else {
            st.push(stoll(t));
        }
    }
    return st.top();
}
```

**Basic Calculator II (227)** — handle `*` and `/` before `+` and `-`:
```cpp
// Stack stores resolved terms. Flush on '+'/'-', compute on '*'/'/'
int calculate(string s) {
    stack<int> st;
    int num = 0;
    char sign = '+';
    for (int i = 0; i < s.size(); i++) {
        char c = s[i];
        if (isdigit(c)) num = num * 10 + (c - '0');
        if ((!isdigit(c) && c != ' ') || i == s.size() - 1) {
            if (sign == '+') st.push(num);
            else if (sign == '-') st.push(-num);
            else if (sign == '*') { int t = st.top(); st.pop(); st.push(t * num); }
            else if (sign == '/') { int t = st.top(); st.pop(); st.push(t / num); }
            sign = c;
            num = 0;
        }
    }
    int res = 0;
    while (!st.empty()) { res += st.top(); st.pop(); }
    return res;
}
```

**Key insight**: Defer addition/subtraction to the end (sum the stack). Handle multiplication/division immediately (modify top of stack).

## Pattern 6 — Stack-Simulated Recursion / DFS

### 📖 Notes & Theory

**What it is**: Replace the call stack of a recursive algorithm with an explicit stack. Primarily used to make tree traversals iterative, avoid stack overflow, or traverse graphs iteratively.

**How to identify**:
- "Iterative inorder/preorder/postorder traversal"
- "DFS without recursion"
- Any recursion-heavy problem where the interviewer asks for an iterative solution
- Keywords: "iterative", "without recursion", "explicit stack"

**Iterative Inorder Traversal**:
```cpp
void inorder(TreeNode* root) {
    stack<TreeNode*> st;
    TreeNode* curr = root;
    while (curr || !st.empty()) {
        while (curr) { st.push(curr); curr = curr->left; }
        curr = st.top(); st.pop();
        // process curr
        curr = curr->right;
    }
}
```

**Iterative Postorder (tricky)** — reverse of modified preorder:
```cpp
// Preorder: root → left → right
// Modified preorder: root → right → left
// Postorder = reverse of modified preorder
vector<int> postorder(TreeNode* root) {
    if (!root) return {};
    stack<TreeNode*> st;
    vector<int> res;
    st.push(root);
    while (!st.empty()) {
        auto node = st.top(); st.pop();
        res.push_back(node->val);
        if (node->left) st.push(node->left);
        if (node->right) st.push(node->right);
    }
    reverse(res.begin(), res.end());
    return res;
}
```

**Graph DFS**:
```cpp
void dfs(int start, vector<vector<int>>& adj) {
    stack<int> st;
    vector<bool> visited(n, false);
    st.push(start);
    while (!st.empty()) {
        int node = st.top(); st.pop();
        if (visited[node]) continue;
        visited[node] = true;
        for (int neighbor : adj[node]) st.push(neighbor);
    }
}
```

## Pattern 7 — Min / Max Stack (Auxiliary Stack)

### 📖 Notes & Theory

**What it is**: Maintain a second auxiliary stack that tracks the running minimum or maximum. Every time you push to the main stack, also push to the auxiliary stack if the new element is ≤ current min (or ≥ current max). Pop from both stacks together.

**How to identify**:
- "Design a stack that supports push, pop, top, and retrieving the minimum in O(1)"
- Sliding window maximum/minimum (deque variant)
- Keywords: "O(1) min", "O(1) max", "retrieve minimum at any time"

**Min Stack implementation**:
```cpp
class MinStack {
    stack<int> main, minSt;
public:
    void push(int val) {
        main.push(val);
        if (minSt.empty() || val <= minSt.top()) minSt.push(val);
    }
    void pop() {
        if (main.top() == minSt.top()) minSt.pop();
        main.pop();
    }
    int top() { return main.top(); }
    int getMin() { return minSt.top(); }
};
```

**Space-optimized variant** — store `(value, currentMin)` pairs in a single stack:
```cpp
stack<pair<int,int>> st; // {value, minSoFar}
void push(int val) {
    int curMin = st.empty() ? val : min(val, st.top().second);
    st.push({val, curMin});
}
```

**Sliding Window Maximum (239)** — use a **monotonic deque** (double-ended queue):
```cpp
// Deque stores indices; front = current window max
deque<int> dq;
for (int i = 0; i < nums.size(); i++) {
    while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();
    dq.push_back(i);
    if (dq.front() <= i - k) dq.pop_front(); // out of window
    if (i >= k - 1) res.push_back(nums[dq.front()]);
}
```

## Pattern 8 — Decode / Sequence Reconstruction

### 📖 Notes & Theory

**What it is**: Build a result character by character (or digit by digit), using a stack as a scratchpad. The stack lets you "undo" or "backtrack" to a previous state when you encounter a special character.

**How to identify**:
- "Decode string", "remove k digits", "make lexicographically smallest"
- The output is built incrementally, and sometimes recent choices must be undone
- Keywords: "remove", "decode", "reconstruct", "smallest subsequence"

**Decode String (394)**:
```cpp
string decodeString(string s) {
    stack<pair<int, string>> st; // {repeatCount, builtString}
    string curr = "";
    int k = 0;
    for (char c : s) {
        if (isdigit(c)) {
            k = k * 10 + (c - '0');
        } else if (c == '[') {
            st.push({k, curr});
            curr = ""; k = 0;
        } else if (c == ']') {
            auto [times, prev] = st.top(); st.pop();
            string repeated = "";
            for (int i = 0; i < times; i++) repeated += curr;
            curr = prev + repeated;
        } else {
            curr += c;
        }
    }
    return curr;
}
```

**Remove K Digits (402)** — monotonic stack building smallest number:
```cpp
string removeKdigits(string num, int k) {
    string st = "";
    for (char c : num) {
        while (k && !st.empty() && st.back() > c) {
            st.pop_back(); k--;
        }
        st += c;
    }
    while (k--) st.pop_back();
    // trim leading zeros
    int start = st.find_first_not_of('0');
    return start == string::npos ? "0" : st.substr(start);
}
```

## Pattern 9 — Stock Span / Online Algorithms

### 📖 Notes & Theory

**What it is**: Process elements one at a time (online), and for each element, answer a query based on previously seen elements. The monotonic stack enables O(1) amortized answers by discarding elements that can no longer be useful.

**How to identify**:
- Elements arrive one at a time (online / streaming)
- "Span of stock price", "number of days until warmer", "how many consecutive previous days had lower price"
- Keywords: "consecutive", "span", "previous consecutive", "online"

**Stock Span (901)**:
```cpp
class StockSpanner {
    stack<pair<int,int>> st; // {price, span}
public:
    int next(int price) {
        int span = 1;
        while (!st.empty() && st.top().first <= price) {
            span += st.top().second; // absorb span of popped element
            st.pop();
        }
        st.push({price, span});
        return span;
    }
};
```

**Key insight**: When you pop an element, its span is absorbed into the current element's span. This is the "span compression" trick that gives O(1) amortized.

**Relationship to Pattern 2**: Stock span is "previous greater element" computed online. Pattern 2 processes all elements at once; Pattern 9 processes one at a time.

## Pattern 10 — Monotonic Stack on 2D / Matrix

### 📖 Notes & Theory

**What it is**: Apply histogram-style monotonic stack logic **row by row** on a 2D binary matrix. Each row is treated as the base of a histogram where column heights accumulate consecutive 1s.

**How to identify**:
- "Maximal rectangle in binary matrix"
- "Largest area of 1s in a grid"
- Any histogram problem extended to a matrix
- Keywords: "binary matrix", "grid", "2D", "rows of heights"

**Algorithm skeleton (Maximal Rectangle)**:
```cpp
int maximalRectangle(vector<vector<char>>& matrix) {
    int m = matrix[0].size();
    vector<int> heights(m, 0);
    int maxArea = 0;

    for (auto& row : matrix) {
        // Build heights row by row
        for (int j = 0; j < m; j++) {
            heights[j] = (row[j] == '1') ? heights[j] + 1 : 0;
        }
        // Apply largest rectangle in histogram on heights
        maxArea = max(maxArea, largestRectangleInHistogram(heights));
    }
    return maxArea;
}
```

**Key insight**: This is Pattern 3 (histogram) applied iteratively, once per row. The height of each column is the number of consecutive 1s ending at the current row.

## Hybrid Decision Guide

> When a problem feels like it belongs to TWO patterns, use the **dominant pattern rule**: ask "what is the PRIMARY structure driving the solution?"

| Combination | Rule | Example |
|---|---|---|
| Stack + Queue | Stack if LIFO; Queue/Deque if FIFO or sliding window | 232, 239 |
| Mono Stack + DP | Mono stack if per-element NGE; DP if optimal substructure | 907 vs 53 |
| Parentheses + Expression | Parentheses if matching only; Expression if evaluating values | 20 vs 224 |
| Histogram + 2D | Use P3 subroutine inside P10 row-by-row loop | 84 inside 85 |
| Stack + BFS | Stack = DFS; Queue = BFS — choose by traversal order needed | 94 vs 102 |
| Decode + Parentheses | Decode if building a result; Parentheses if just validating | 394 vs 20 |
| Mono Stack + Span | Offline (array given) → P2; Online (one at a time) → P9 | 739 vs 901 |
| Min Stack + Sliding Window | Fixed window → P7 deque; No window → P7 aux stack | 239 vs 155 |

## Quick Reference — Common Mistakes

| Mistake | Correct Approach |
|---|---|
| Storing values instead of indices in monotonic stack | Store **indices** — you need position to compute width/distance |
| Forgetting the sentinel `0` in histogram problems | Append `0` to heights array to flush remaining stack elements |
| Using `stack<int>` instead of `deque<int>` for sliding window max | Use `deque` for O(1) access to both ends |
| Not handling multi-digit numbers in calculator problems | Use `num = num * 10 + (c - '0')` and only process on operator/end |
| Popping from empty stack without checking | Always guard with `!st.empty()` before `st.top()` or `st.pop()` |
| Forgetting to backtrack deque front for out-of-window indices | Check `dq.front() <= i - k` and pop front when out of window |
| Wrong order of pop vs push in min stack | Pop from minStack only if `main.top() == minSt.top()` |
| Not stripping leading zeros in Remove K Digits | Use `find_first_not_of('0')` after building the result |
| Confusion between `(` push and `)` pop direction | Always push on open bracket; pop and match on close bracket |
| Not initializing base index `-1` in Longest Valid Parentheses | Push `-1` as the initial base so `i - st.top()` is correct |
